🧠 第 1 页：一张图看懂链接

三个必须分清的概念

概念 说明
静态库 libSDL2.a 链接时把库代码整体拷进你的 exe。几十 MB
导入库 libSDL2.dll.a / SDL2.lib 只记录"函数在 DLL 的什么位置"。几十 KB 的符号表
DLL SDL2.dll 真正的实现，运行期才被加载。~2 MB

⚠️ libSDL2.a（静态库）和 libSDL2.dll.a（导入库）是两个完全不同的文件，只是名字长得像。
同一个 -lSDL2 会按 libSDL2.dll.a → libSDL2.a → SDL2.lib 的顺序找，谁先找到算谁 —— 所以想静态链接要指定全名（见第 11 页）。

🎯 第 4 页：SDL2 的特殊之处

为什么有的 SDL 程序要链 -lSDL2main

Windows 分两种程序：

类型 入口符号 控制台
控制台程序 main / WinMain 有黑框
GUI 程序 WinMain 无黑框

SDL2 要开图形窗口，它把你的 main 改名成 SDL_main（靠 SDL.h 里的 #define main SDL_main），然后需要一个 WinMain 来启动 —— 这个 WinMain 由 SDL2main 库提供。

三种处理方式

方式 命令行 需要哪些 DLL 说明
① 链 SDL2main -lSDL2main -lSDL2 SDL2main.dll + SDL2.dll 最"标准"的做法
② 手动声明 ⭐ -lSDL2 只要 SDL2.dll 少一个依赖，本文用这个
③ 纯静态 -static -lSDL2 无 需 SDL2 编译时开 SDL_STATIC_LIBSDL2_MAIN

方式 ② 怎么写：

两种 include 写法

写法 需要哪个 -I
#include <SDL.h> include/SDL2（老风格）
#include <SDL2/SDL.h> include（推荐，有前缀不撞名）

推荐用 <SDL2/SDL.h>，这样只需 -I.../include，不用加两遍。

解法：MinGW 程序配 MinGW 库，MSVC 程序配 MSVC 库。

📎 附录 C：ABI 兼容（MinGW 库 vs MSVC 库不能混）

为什么不能混

ABI（应用二进制接口）包括：参数传递方式、结构体内存布局、C++ 名字修饰规则、异常机制、std::string/std::vector 的内部实现。

MSVC 和 GCC 的 ABI 完全不同，混用会导致参数传错、行为诡异、运行崩溃。

判断库是哪个编译器编的

兼容组合（挑一套，别混）

你的编译器 库要选 vcpkg triplet 下载文件名
MinGW-w64 (GCC) MinGW 构建 x64-mingw-dynamic / x64-mingw-static xxx-mingw.zip
MSVC (cl.exe) MSVC 构建 x64-windows-dynamic / x64-windows-static xxx-VC.zip

一句话记忆：-mingw 结尾 = 给 MinGW；-VC 结尾 = 给 MSVC。

兼容性技巧：纯 C 接口

用 extern "C" 的纯 C 接口 ABI 差异会小很多（无重载、无 mangling）。
但结构体 padding/对齐规则仍可能不同 → 最安全还是全套统一。

🎯 结语：链接外部库的思维模型

# 要点 内容
1 三样东西三个期 头文件（编译期）+ 库文件（链接期）+ DLL（运行期），缺一不可
2 分层诊断 -I 管头文件、-L/-l 管库、拷 DLL 管运行。一次只查一层
3 -fsyntax-only 是你的诊断利器 把"头文件找不到"和"库找不到"分开，一次解决一个
4 链接顺序：使用者在前 有疑问用 -Wl,--start-group ... -Wl,--end-group
5 ABI 必须统一 MinGW 程序配 MinGW 库，别混 MSVC
6 优先用包管理器 vcpkg / MSYS2 / apt / brew。手动维护路径是长期痛苦
7 偷看工具怎么算参数 cmake --build build --verbose、pkg-config --cflags --libs xxx

🎯 一句话总结：
用命令行手敲一遍，你就知道每个 -I -L -l 到底在干什么。
之后再用 IDE/CMake/vcpkg —— 那些工具只是帮你算出这些参数，不是替你理解它们。
