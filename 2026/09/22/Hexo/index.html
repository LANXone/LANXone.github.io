一、先搞懂这堆名词都是啥

在开始之前,先把所有会提到的英文名词翻成大白话,后面看到就不会懵了:

名词 是什么 大白话解释
Hexo 静态博客框架 一种工具,你写 Markdown 文章,它帮你变成漂亮的网页,最后直接扔到 GitHub Pages 就能看
GitHub Pages GitHub 免费静态网站托管 GitHub 提供的免费空间,专门放网页,每个人都有一个 xxx.github.io 的地址
Node.js JavaScript 运行环境 让 JS 能在电脑上跑的程序,类似 Python,装了它才能跑 Hexo
Markdown 轻量级标记语言 一种写文章的格式,用 # 表示标题,- 表示列表,比 Word 简单
CSS 层叠样式表 控制网页"长什么样"的语言,比如颜色、字体大小、圆角
JavaScript (JS) 网页交互语言 控制网页"做什么事"的语言,比如点按钮弹出提示、复制链接
CDN 内容分发网络 全球分布的文件服务器,加速用户下载。比如你加载 KaTeX 样式,CDN 帮你从最近的服务器取文件
DNS 域名系统 把 lanxone.github.io 翻译成电脑能懂的 IP 地址。DNS 同步 = 全世界的服务器都知道这个新地址了
环境变量 配置项 存密码、API Key 这类敏感信息的地方,不会被写进代码里推到 GitHub 上

后端和数据库相关名词

名词 是什么 大白话解释
后端 (Backend) 跑在服务器上的程序 浏览器和数据库之间的中间商。浏览器说"我要发评论",后端说"好的我存起来了"
数据库 (Database) 存数据的程序 专门存东西的仓库,比如评论、点赞数、访客计数
MongoDB 一种流行的数据库 像一个巨大的 JSON 文件仓库,存东西很灵活,不需要提前定义格式
MongoDB Atlas MongoDB 官方提供的云服务 MongoDB 官方帮你把数据库存在他们的服务器上,免费额度够用
Vercel 云函数/静态网站平台 一个部署后端和前端的平台,和 GitHub 集成很方便,免费额度够用
Netlify Vercel 的竞争对手 功能几乎一样,但国内访问比 Vercel 快很多。当时差点选它
Twikoo 评论系统 我们选的评论系统,只有前端(React)没有后端,后端要我们自己部署
Valine 另一个评论系统 Twikoo 的竞争对手,后端用 LeanCloud,但国内的 LeanCloud 已经废了
Giscus 基于 GitHub Discussions 的评论 最简单的评论方案,评论数据直接存在你 GitHub 的 Discussions 里,但读者必须有 GitHub 账号才能留言
LeanCloud 国内的 BaaS 平台 曾经是 Valine 的后端,但国际版已经停服,国内版要收费
busuanzi (不蒜子) 国内的访客统计服务 免费的 PV/UV 统计,就是我加在页脚的"总访客/总浏览"

为什么选 Twikoo + Vercel + MongoDB?

这个组合是当时筛选了至少 3 个方案后定下来的,对比一下:

方案 后端 数据库 优点 缺点 为啥没选
A. Giscus 无(用 GitHub) GitHub Discussions 零后端,最省心 读者必须有 GitHub 账号 ❌ 访客门槛太高,体验差
B. Valine LeanCloud LeanCloud MongoDB 老牌、教程多 LeanCloud 国际版已死,国内版收费 ❌ 后端用不了
C. Twikoo + Vercel + MongoDB Atlas Vercel (免费) MongoDB Atlas (免费 512MB) 读者不需要账号就能留言,点赞/访客也有 Vercel 默认域名国内可能慢 ✅ 综合最优,免费 + 无门槛
D. Twikoo + Netlify Netlify (免费) MongoDB Atlas 和 C 一样,但国内更快 和 C 一样 ⚠️ 备选,Vercel 太慢就换这个

三、问题 1:数学公式显示乱码

现象

文章里写的 LaTeX 公式(比如 $L$、$C$),渲染出来是一堆纯 HTML 标签,没有样式。

根因

  • Markdown 渲染成功了(页面里已经有 <span class="katex">...</span> 结构)
  • 但 KaTeX 的 CSS 样式文件没加载,就像 HTML 骨架没穿衣服

解决方案

用 Hexo 官方的 injector API,在每个页面的 <head> 末尾注入 KaTeX 的 CDN 样式:

文件:scripts/katex.js(新建)

为什么不用其他方案

方案 为什么没选
在 _config.yml 里配 markdown-it-katex 你已经装了,它只负责生成 HTML,不负责 CSS

injector API Hexo 官方推荐,一行代码搞定,不碰主题文件

六、问题 4:加留言板 + 评论系统选哪个

需求梳理

我想要:

  1. 留言板页面(专门给访客留言的地方)
  2. 每篇文章底部有评论区
  3. 文章底部有点赞按钮
  4. 页脚有访客统计
  5. 最好都免费

筛选过程

❌ 淘汰方案 A:Valine

  • 后端用 LeanCloud,国际版已经停服了(访问 leancloud.cn 会报错)
  • 国内版虽然还在,但要实名、要绑定银行卡,门槛太高

❌ 淘汰方案 B:Giscus

  • 后端是 GitHub Discussions,零后端,简单
  • 但读者必须有 GitHub 账号才能留言,普通人没有 GitHub,体验差

✅ 选中方案:Twikoo + Vercel + MongoDB Atlas

  • Twikoo 前端 + 自己部署 Vercel 后端 + MongoDB Atlas 数据库
  • 读者无需注册、无需账号,填昵称和邮箱就能留言
  • 三个都是免费的,加起来零成本

Twikoo 有啥 API?

Twikoo 官方文档里列的独立 API:

API 功能 我们用了吗

twikoo.getVisitorCount() 获取 PV/UV 访客计数 ❌ 没用在独立站点统计上(返回的数据格式不确定)

七、问题 5:部署评论后端(Vercel + MongoDB)

这是最折腾的一步,分两部分:先建数据库,再部署后端。

7.1 建 MongoDB Atlas 数据库

MongoDB Atlas = MongoDB 官方提供的云数据库服务,永久免费,512MB 存储够几千条评论用了。

步骤(已实际走过)

第 1 步:打开 https://www.mongodb.com/cloud/atlas ,用邮箱或 GitHub 账号注册登录

第 2 步:点 Build your first database,选 M0(免费套餐),地域选 Singapore 或 N. Virginia(不要选中国,免费层没有中国节点)

第 3 步:配置网络访问 —— 默认情况下数据库不让外部连接,需要手动放行。左侧菜单 Security → Network Access → Add IP Address → 填 0.0.0.0/0(意思是"任何 IP 都能连")→ Confirm

第 4 步:创建数据库用户 —— Security → Database Access → Add New Database User,权限选 Atlas admin(超级管理员,简单),用户名随便起(比如 twikoo),密码点那个🔑方块自动生成 → 复制保存密码,只显示一次!

第 5 步:复制连接字符串 —— 回到集群页面,点 Connect → Drivers,选 Node.js,Version 4.1+,复制那个 mongodb+srv://... 开头的字符串,把里面的 <db_username>:<db_password> 换成你刚才的真实用户名和密码

⚠️ 密码里有特殊字符怎么办?
如果密码里有 @ : / # 这些符号,需要 URL 编码(@ 变成 %40,: 变成 %3A)。自动生成的强密码经常有,如果不确定就手动换成纯字母数字的密码。

Vercel = 部署后端和前端的平台,和 GitHub 集成很方便。

步骤(已实际走过)

第 1 步:打开 https://vercel.com ,用 GitHub 账号一键登录

第 2 步:点这个官方模板一键部署 Twikoo:

👉

第 3 步:会跳转到 Vercel 的 Import Project 页面,Git Scope 选你的账号,Repository Name 随便起(比如 twikoo),点 Create

第 4 步:进入部署页面,往下滚找到 Environment Variables,Key 填 MONGODB_URI,Value 填你刚才替换好用户名密码的完整连接串,勾上 Production,Deploy

第 5 步:等 1-2 分钟,状态变成 Ready ✅,在 Project → Overview 页面复制那个 https://xxx.vercel.app 的地址 —— 这就是你的 Twikoo 后端地址(envId)

中间踩的坑

坑 原因 怎么解决
第一次 Deploy 报错 {"code":1000,"message":"MONGODB_URI"} 没填环境变量 Settings → Environment Variables → Add,Key=MONGODB_URI,Value=连接串,Save 后去 Deployments → Redeploy
拿到的域名是 twikoo-topaz-ten.vercel.app,不是预期的 twikoo-topaz-vercel.app Vercel 自动分配的域名后缀可能带 -ten、-fifteen 等随机后缀 看 Vercel Domains 页面显示的真实域名,不要自己猜
绑定自定义域名 twikoo.lanxone.github.io 报 Invalid Configuration .github.io 是 GitHub 管理的域名,你没有权限在上面创建 CNAME 记录 放弃绑自定义域名,或者买一个真·域名(比如 lanxone.com)再绑
电脑上打不开 Vercel 默认域名 ERR_NAME_NOT_RESOLVED / ERR_CONNECTION_TIMED_OUT Vercel 默认域名的 DNS 全球传播需要时间;且 Vercel 在国内访问普遍较慢 等 DNS 同步(几小时);或者用手机流量试试(不同运营商缓存);实在不行换 Netlify

八、问题 6:评论 UI 太丑 + Powered by 隐藏

Twikoo 自带的 UI 是 Element Plus 的默认样式,比较朴素,而且底部有个 "Powered by Twikoo" 链接想藏起来。

解决方案:纯 CSS 覆盖

所有样式写在 scripts/twikoo.js 里,用 <style> 标签注入。为什么不写单独的 CSS 文件?因为 Hexo 的 injector API 支持这样注入,一个文件搞定,不用额外管静态资源路径。

具体改了什么

改动 CSS 选择器 效果
评论区加圆角卡片容器 #twikoo-comments 白底、圆角 14px、轻微阴影
留言板特殊样式 body.page-guestbook #twikoo-comments 蓝色渐变背景,和文章页区分
提交按钮渐变色 .tk-btn-primary 紫色渐变 #6366f1 → #8b5cf6、圆角 20px
评论卡片化 .tk-comment-item 每条评论加浅灰边框、浅灰背景、hover 微阴影
隐藏 Powered by #twikoo-comments a[href*="twikoo"] display:none !important
头像圆形化 .tk-avatar img border-radius: 50%
Toast 提示 .lanx-toast 复制链接成功时顶部弹出的小气泡

隐藏 Powered by 踩的坑

第一次 CSS 选择器写了 .tk-comment-footer a[href*="twikoo"],但 Twikoo 渲染出来的结构里那个 <a> 不在 footer 里,是个裸的 <a href="https://twikoo.js.org">Twikoo</a>。

正确选择器:#twikoo-comments a[href*="twikoo"] —— 更宽泛,只要在评论容器里、href 包含 "twikoo" 的全部藏起来。

九、问题 7:评论失败 + 点赞数 + 阅读数

9.1 评论失败的原因

根本原因:浏览器打开评论区时,Twikoo 会立即向后端发请求。如果 Vercel 的 DNS 还没同步(国内电脑常见),请求就会报 ERR_NAME_NOT_RESOLVED,Twikoo 会显示红色错误提示。

解决方案:先 Ping 后端再渲染 Twikoo

不是一上来就调用 twikoo.init(),而是先发一个 fetch(envId) 请求试试后端能不能通:

mode: 'no-cors' 是什么?
跨域请求的一种模式,fetch 发出去后不关心返回内容,只要请求没报错就算成功。用来做"连通性检测"刚好,不需要解析返回值。

降级提示长啥样:一个黄色警告卡片 ⚠️,写着 "评论服务暂时不可用,请稍后刷新页面再试~",比 Twikoo 默认的红色错误友好多了。

9.2 点赞功能

Twikoo 没有独立的文章点赞 API,所以点赞只能存 localStorage。

localStorage 是什么?
浏览器提供的"小仓库",网页可以在里面存一些字符串,下次打开还在。和 cookie 类似,但不会随请求发送到服务器。缺点:换个浏览器/设备就清零了。

实现方案:

  • 点赞状态:localStorage.getItem('liked_' + path) → 存在 = 已点赞
  • 点赞计数:localStorage.getItem('likeCount_' + path) → 每次点赞 +1
  • 每次点赞,按钮上的数字和页脚里内联的数字实时同步

9.3 文章阅读数

用 Twikoo 自带的 #twikoo_visitors span。Twikoo 初始化时会自动把这个 span 替换成当前文章的 PV(Page View,页面浏览量)。

十、问题 8:分享链接错了 + 评论区默认收起

10.1 分享链接复制的是 example.com

根因:_config.yml 里的 url: 还是占位符 http://example.com,模板渲染时把这个塞进了 .article-share-link 的 data-url 属性。

解决方案:不读 data-url,直接读浏览器当前地址:

location.origin 和 location.pathname 是什么?

  • location.origin = https://lanxone.github.io(协议 + 域名 + 端口)
  • location.pathname = /2026/09/22/链表环检测/(路径)
  • 拼起来就是完整且准确的地址

10.2 评论区默认收起

用户反馈评论区太长,想隐藏起来,点一下才展开。

实现:

  • 文章页:评论区外层加一层 <div id="twikoo-comments-body" style="display:none;">,上面放一个大按钮 💬 展开评论区
  • 留言板:不折叠(本来就是专门来留言的,没必要藏)
  • 用户点展开时,把 style.display 改成空字符串,按钮文字变成 🙈 收起评论区
  • Twikoo 初始化也延迟到用户第一次点展开之后才调用(避免渲染隐藏元素的兼容性问题)

十一、问题 9:主页分页

为什么改完 per_page: 5 没看到分页

Hexo 只在需要翻页的时候才会渲染分页导航。你有 5 篇文章,per_page: 5,刚好一页装完,所以没分页。

injector 的三个选项

Hexo 的 injector 有 3 个参数,常用的 position 选项:

body_start <body> 之后 页面一开始就要加载的东西
body_end </body> 之前 JS 脚本、页面底部元素
