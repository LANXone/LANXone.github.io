写在最前面：先记住三句话

1. 你现在最该做的事只有一件：买一块 STM32 开发板，今晚就下单。

不是因为它有多重要，而是因为它是一个能立刻开始的动作。职业规划最怕的就是"想了很多但什么都没做"。

2. 你最大的优势是地理和时机。

广东的嵌入式产业布局（深圳的芯片/方案公司、广州的工业和汽车、东莞的制造）是你择校时带来的红利。留在广东，就业机会比大多数省份多得多。 不要轻易去外地。

3. 这四年不是要"赢过谁"，是要"建成一套能变现的能力"。

不用焦虑对比同学。你只需要每年比现在强一点。大二会 STM32，大三有项目 + 实习，大四拿 offer —— 这就够了。

从数据里能读出的三个判断

判断一：这个专业在广工是优势专业，不是垫底专业。

排名进前 7 意味着课程体系、师资、认可度都不差。你不需要为了逃避专业而焦虑。 物联网工程是当前国家战略方向，不会过时。

判断二：地理优势极大。

63% 去广州、13% 去深圳 —— 而嵌入式/物联网的产业全在这里。这意味着你留在广东就有岗位，不用北上广深杭卷。区域选择本身就是一种竞争力。

判断三：起点薪资 6287 不高，但这正常。

广工不是华工/中山，0年经验 6K 左右是合理价位。关键不是起点多高，是 5 年后能不能到 12477 甚至更高。

而这个数字取决于你选的赛道（见下一节）。

二、嵌入式行业全景：分赛道决定薪资

残酷的真相：同样叫"嵌入式工程师"，应届起薪差 3 倍

我在招聘数据里发现一个极其残酷的分层：

方向 应届起薪 3-5年 5年+ 核心溢价点 现状评价
传统单片机（消费电子） 6-9K 15-25K 30-40W 低成本方案、量产交付、兼容性 🔴 低端内卷严重
物联网网关 / 云边协同 8-12K 18-28K 20-30W MQTT、LoRa/NB-IoT、云平台对接 🟡 稳定但溢价有限

注意第一行和最后一行的差距：应届起薪 6-9K vs 14-20K，差 3 倍。

行业里流传一句话叫"嵌入式分赛道，选错等于白干" —— 我在招聘数据里看到，有人做蓝牙耳机月薪 8K 还得天天加班，有人做工业控制 20K 起还能双休。

关键洞察：这个分层不由"你聪不聪明"决定，而由"你选的细分赛道"决定。 新人无法改变行业，只能选赛道。

嵌入式的三个现实痛点（要知道，别幻想）

  1. 入门门槛比互联网高 —— 必须吃透 C/C++、操作系统、硬件时序、电路图、通信协议，前期学习周期长
  2. 低端岗位内卷严重 —— 只会基础单片机没高阶项目，只能混小家电行业
  3. 工作环境相对辛苦 —— 经常面对示波器、电路板、车间调试，比坐办公室写代码累

但也有对应优势：技术壁垒强，不容易被替代，裁员风险小。

三、我的方向建议

首选：嵌入式 Linux 驱动 / 边缘 AI

理由：

  1. 起薪最高（应届 18-25K），和传统单片机差 3 倍
  2. 技能可迁移 —— 学会了在任何芯片平台都能用，不像单片机那样绑死某个芯片
  3. 不担心 35 岁 —— 这是少数越老越值钱的领域，硬件调试经验需要长年累月实操沉淀
  4. 广东需求旺盛 —— 深圳一堆芯片公司、方案公司

风险： 学习曲线陡。需要先打好 C + 操作系统 + 驱动基础。

次选：车载电子

理由： 稳定性最好，几乎不裁员，5 年后 60-100W。

风险： 门槛稍高（AUTOSAR、ISO 26262 功能安全要求），岗位主要集中在深圳、上海。

避开：传统消费电子单片机

理由： 这是嵌入式里的"低端内卷"区。新人只能做重复性工作，成长空间小，天花板低。

备选：物联网网关 / 云边协同

理由： 和你专业最对口，MQTT/LoRa/NB-IoT + 云平台对接，技术栈广。

不足： 溢价有限（8-12K 起）。如果你想在这个方向做出差异，需要叠加边缘 AI 或 Linux 驱动技能。

决策建议

大一大二先不急着定死方向。 你现在只需要做一件事：

先把 STM32 学会，做到能独立完成项目。 有了这个基础，你在大二末、大三初就能真正判断自己对哪类技术感兴趣、擅长什么。

方向是在实践中试出来的，不是在大一就规划出来的。

四、当下（大二上）该做什么

这是本笔记最核心的部分。

时间分配的真相

按每周 20 小时课外时间算（学业之外能挤出的时间）：

投入方向 时长 占比 理由
STM32 + 嵌入式基础 8h 40% 专业对口，最直接
C++ 现代化 + 算法 5h 25% 跨所有方向，面试必问
英语 3h 15% 考研/外企/读文档都需要
信息源跟踪 2h 10% 知道行业在发生什么

注意最后一行。 我见过太多人两个月废寝忘食然后倦怠退场。

持续性比强度重要得多。 每天 2 小时 × 300 天 = 600 小时，胜过一周突击 40 小时然后停摆三个月。

具体的四件事

① 硬件：买一块 STM32 开发板，动手

这是本学期最高 ROI 的投入。

项目 内容
买什么 STM32F103C8T6 最小系统板（淘宝十几块）或 F407（贵一点但资料多）
学什么 跟着江科大自化协的 STM32 视频（一整套，几十小时）
学到什么算过关 能独立用 HAL 库点亮一个 LED、读温湿度传感器（DHT22）、通过串口和电脑通信
额外建议 去问自动化学院老师能不能进实验室，有实验室经历在简历上是硬加分

为什么必须动手：

嵌入式是"软硬件两手抓"的行业，看视频学不会。你必须经历：

  • 程序烧不进去
  • 传感器读数是乱的
  • 时序对不上
  • 硬件坏了查半天

这种痛才是真正的学习。

配套要补的理论（同步看，不要等）：

  • 《数字电子技术基础》/《模拟电子技术基础》（你现在正在学的课，务必学扎实）
  • 《微机原理与接口技术》（如果有）
  • 单片机原理、时序分析

② C++：从"能用"到"懂原理"

你现在的 C++ 水平是"有一定基础"。这是好消息，比完全零基础快很多。

本学期要补的：

内容 为什么重要
指针 / 内存模型 嵌入式面试必问，也是理解 C 的基础
RAII 和智能指针 资源管理在嵌入式里极其重要（句柄、文件、内存都要管）
STL 容器 至少 vector、map、queue、array
现代 C++ 特性（C++11 之后） auto、lambda、move、智能指针、范围 for

怎么学： 不用买书。B站上有大量高质量的现代 C++ 教程，跟着敲一遍，再自己写小项目。

具体练手项目（正好用上你之前学的）：

把 GLFW 的 hello window 用 C++ 重新组织一遍 —— 封一个 Window 类，用 RAII 管理 GLFW 的初始化和销毁：

这个小练习能同时练到：封装、构造析构、拷贝禁用、RAII、常量正确性。 比你抄十遍教程有用。

③ 英语：别因为高考结束就放下

这是最容易被忽视、但回报极高的投资。

原因很实在：

  • 嵌入式领域的技术文档全是英文 —— 芯片手册、RTOS 官方文档、寄存器说明
  • 外企和合资企业要求英语（宝马、华为国际、汇丰、博世等）
  • 考研需要（哪怕你可能不考）
  • CSDN / 博客园的技术文章质量差一大截，想深入必须看英文原版
  • 官方文档是最好的学习材料 —— ST 的参考手册、FreeRTOS 官方文档

具体做法：

  • 每天 30 分钟，看英文技术文档
  • 首选材料：STM32F1xx Reference Manual（芯片手册）、FreeRTOS 官方文档、GLFW 官方文档
  • 不用刻意背单词，但要能看懂技术英语（术语重复率高，熟了就会）
  • 遇到生词就查，积累技术词汇

这招还有个副作用：你现在的 GLFW 官方文档就是英文的，读它就是免费的英语学习材料。

④ 跟踪信息源：知道行业在发生什么

很多学生到大三还对行业一无所知，这是最大的信息差。

建议关注：

类型 具体推荐
招聘平台 BOSS直聘、实习僧（现在就可以去刷）
行业新闻 电子发烧友、芯智讯、EEWorld
开源社区 RT-Thread、Zephyr、ESP-IDF 社区（看别人在做什么）
视频/图文 B站、小红书搜"嵌入式学习路线"，过来人会分享踩坑经验
官方文档 直接读 ST、FreeRTOS、ESP-IDF 的官方文档

具体动作（本周就做）：

打开 BOSS直聘 / 实习僧，搜索"嵌入式"，翻 20-50 个岗位的 JD，把出现频率最高的技能词抄下来。

这就是你的学习清单，比任何规划文章都准。

为什么这件事优先级这么高： 因为它成本极低（1 小时）但信息价值极高。它能告诉你：

  • 现在的市场到底要什么
  • 哪些技能是"必须"哪些是"加分"
  • 哪些岗位是给应届生的，哪些是给有经验的
  • 薪资区间的真实分布（不是招聘软件上的虚标）

大三下（2028 春）—— 实习 + 秋招

这是决定你最终 offer 质量的月份。

任务 优先级 说明
找实习 🔴 最高 目标：2 段，累计 3-4 个月
秋招准备 🔴 最高 简历 + 刷题 + 八股文
简历打磨 🟠 高 让有经验的人帮你看
刷题 🟠 高 编程题 + 嵌入式专项
毕设选题 🟡 中 越早越好，别拖到大四

为什么实习这么重要：

  • 嵌入式行业极度看重实习经历，因为上手成本高，公司不想招"需要从头培养"的人
  • 有实习经历的应届生和没实习的，简历通过率差几倍
  • 广工在广州，深圳实习资源丰富，学校又有 50+ 就业基地
  • 大三下没实习，大四秋招只能和有实习的人竞争，你会后悔

实习方向选择： 尽量去能做内核/驱动/系统层的岗位，不要去那种只做应用层调用库的公司。实习质量 > 实习数量。

大四上（2028 秋）—— 秋招决战

时间 动作
8-9 月 简历定稿、开始海投

11-12 月 收 offer、比较决策
12 月 兜底（考研/春招准备）

秋招是唯一的黄金窗口。 错过这三个月，就要等明年春招，难度完全不同。

六、三个项目设计

原则：项目要能塞进简历的一行，并且能口述 3 分钟。

核心要求：项目要有"你自己的思考"痕迹，不能是教程照抄。

项目一：智能温湿度监测系统（大二下做）

技术栈：STM32F103 + DHT22 + OLED + WiFi模块 + MQTT + 云端

功能清单：

  • [ ] 实时采集温湿度
  • [ ] OLED 本地显示
  • [ ] WiFi 上报云端（OneNET / 阿里云 IoT 选一个）
  • [ ] 手机或网页查看数据
  • [ ] 亮点：数据异常报警（温度超阈值推送到手机）

涵盖关键词：STM32 / I2C / SPI / UART / MQTT / WiFi / 嵌入式 / 传感器

为什么这个项目好：

  • 覆盖的关键词和招聘要求几乎一一对应
  • 有"云端"部分，能体现完整系统思维
  • 能讲出很多"遇到什么问题、怎么解决"的细节

升级方向（让它不水）：

  • 用 FreeRTOS 而不是裸机（多任务：采集/显示/通信）
  • 自己画 PCB（如果你学了嘉立创EDA）
  • 加数据存储（SD卡 / Flash 掉电保存历史曲线）
  • 加离线告警（断网时也能推送）

项目二：PID 控制智能小车（大三上做）

技术栈：STM32F407 + 编码器 + 电机驱动 + PID 算法 + FreeRTOS + 蓝牙

功能清单：

  • [ ] 编码器闭环测速
  • [ ] PID 算法控制 PWM 输出
  • [ ] 蓝牙遥控 + 路径循迹
  • [ ] 用 FreeRTOS 多任务：控制任务、传感器任务、通信任务
  • [ ] OLED 显示 PID 参数（能现场调参）

涵盖关键词：PID / FreeRTOS / 闭环控制 / 多任务 / 定时器 / 编码器

为什么重要：

这个项目证明你懂控制逻辑和实时系统，不只是"调库"。嵌入式工程师的核心竞争力就是这个。

面试怎么讲：

  • 讲 PID 三个参数怎么调（Kp/Ki/Kd 的作用）
  • 讲超调、震荡怎么解决
  • 讲多任务优先级怎么设计
  • 讲遇到的实际问题（比如编码器测速抖动）

项目三：嵌入式 Linux 小系统（大三上/下做）

技术栈：Linux 开发板（正点原子/野火 ARM 板）+ Linux 驱动 + Qt/图形界面

功能清单（选做）：

  • [ ] 交叉编译 ARM 程序并运行
  • [ ] 写一个字符设备驱动
  • [ ] 交叉编译 Qt 程序做界面
  • [ ] 或者：把 STM32 智能小车升级成 WiFi 控制 + 网页界面

涵盖关键词：Linux 驱动 / 交叉编译 / ARM / 设备树 / Qt

为什么这个项目是分水岭：

Linux 驱动是应届起薪最高的方向（18-25K）。 虽然学习曲线陡，但一旦跨过去，薪资和天花板都不一样。

如果你决定考研，这个项目可以不着急；如果你决定就业，强烈建议做。

九、简历怎么写

❌ 不要这样写

熟练使用 GLFW 进行 OpenGL 图形开发
熟悉 C++，了解 Linux

问题分析：

  • "熟练使用 XXX" 这种句式没有信息量，谁都能说
  • 只写"会用什么"，不写"解决了什么问题"
  • 换库就归零 —— 招聘方看重的是能力，不是你用过什么工具

✅ 应该这样写

嵌入式项目：

基于 STM32F407 + FreeRTOS 实现多任务温湿度监测系统，通过 MQTT 上报至云端；使用 CMake 管理工程，Git 版本控制；在 Linux 下用 GDB 定位并修复多任务竞态问题

C++ 项目：

独立完成基于 C++/OpenGL 的三维渲染器，实现相机控制、光照模型与纹理映射模块；使用 CMake 管理构建流程、GDB 调试定位内存问题

区别在哪：

❌ 弱写法 ✅ 强写法
熟练使用 GLFW 实现相机控制、光照模型
会用 CMake 使用 CMake 管理构建流程
了解 GDB 用 GDB 定位并修复竞态问题
做了温湿度监测 实现多任务 + MQTT 上报 + 修复竞态

后者体现的是"我解决了什么问题"，前者只是"我用过什么工具"。

简历结构建议

项目经历要放最前面，对本科生来说项目比 GPA 更能证明能力。

尽量用数字说话：

❌ 弱 ✅ 强

十一、八个最容易踩的坑

坑 1：学了一堆技术，做不出项目

嵌入式是"实践至上"的学科。你看 100 小时视频，不如花 20 小时调一个传感器 bug。

✅ 验收标准：每学完一块，必须有能跑起来的代码输出。

❌ 典型表现：跟着视频敲了 30 小时代码，一停下来就啥也不会。

坑 2：只学技术，不了解行业

你可能花三个月学完 RTOS，却不知道嵌入式工程师的薪资分层是 6K 到 25K 起步。信息差是最贵的成本。

✅ 验收标准：能清楚说出"我想做车载电子，因为 X 原因，薪资大概 Y"。

坑 3：项目太水，简历没东西写

"基于 STM32 的温湿度监测" 谁都能写，面试官一看就知道是教程照抄。

✅ 升级方法：在教程基础上加一个自己的改进，哪怕很小：

  • 加了数据异常报警
  • 用了 FreeRTOS 而不是裸机
  • 自己画了 PCB
  • 做了手机端界面
  • 做了数据持久化

有"自己的思考"痕迹的项目才值钱。

坑 4：大三下才开始找实习

实习是找实习，不是实习经历。 大三下没实习，大四秋招就只能和有实习的人竞争。你会后悔。

✅ 什么时候开始：大三上就该关注实习信息，大三下开学立刻投。

坑 5：为了"找工作"而考一堆无关证书

CFA、ACCA 对嵌入式工程师完全无用。真正有用的是 CET-4/6、HCIA-IoT、软考初级、驾照。

✅ 原则：证书只考"目标岗位 JD 里明确要求"的。

坑 6：把 GPA 排第一，但项目做得少

成绩固然重要，但嵌入式行业看的是能不能干活。成绩中上 + 项目牛，比成绩第一 + 什么都不会强得多。

✅ 但不要放弃成绩：为了保研/考研/评优/国企，绩点还是要保持。均衡发展，不是二选一。

坑 7：追求"学完"再开始

"等我学完 C 语言就去做项目"、"等我学完 RTOS 就做小车" —— 这是最常见的拖延陷阱。

✅ 正确做法：学 20% 就做 80% 的事。

  • 学了前 20 小时 C 语言 → 立刻做一个小项目（LED 点亮）
  • 学了前 3 天 STM32 → 立刻做一个温湿度采集
  • 学了前 1 周 FreeRTOS → 立刻做一个双任务 LED 闪烁

学不全没关系，用起来再补。

坑 8：一个人闷头做，没人指导

嵌入式领域有很多"看起来很美但实际是弯路"的做法（比如某些特定的库、某些架构）。多和学长、老师、实习生交流，能省下几个月。

✅ 具体做法：

  • 加几个嵌入式学习群/社区（RT-Thread、ESP-IDF 官方群）
  • 关注 2-3 个高质量的技术博主
  • 大三下找到实习后，多问实习生师兄
  • 广工自动化学院有老师答疑渠道，用起来

一、核心概念：三个角色分工

初学者最大的困惑是"这么多工具到底谁干什么"。记住三个角色：

角色 工具 干什么 类比
翻译官 g++ (GCC) 把 .cpp 文本翻译成机器码 翻译
打包工 ar / 链接器 把多个 .o 合并成一个文件 装订
包工头 CMake + make 决定"先做哪个、后做哪个、命令怎么写" 工期表

VS Code 本身不参与编译，它只是：

  • 一个文本编辑器（写代码）
  • 一个配置器（告诉你这些工具怎么用）
  • 一个终端（让你敲命令）

二、编译链路全景

三个阶段的职责

阶段 谁在干 需要什么信息 对应参数
预处理 编译器 头文件在哪 -I
编译 编译器 无 无
链接 链接器 库在哪、要哪些库 -L -l

关键理解

  • .o 是半成品：里面标记着"这里要调用 glfwInit，地址待定"，必须等链接阶段填入真实地址
  • .a 是集装箱：把几十个 .o 打包，这样链接时只要一个参数就能引用全部
  • .exe 是成品：所有需要的 .o 被合并成一个独立文件

类比：.cpp 是菜谱，.o 是切好的食材，.a 是打包好的食材包，.exe 是做好的菜。
链接器就是厨师，负责把食材组合成一道能上桌的菜。

三、后缀速查表

后缀 英文名 中文 类型 能双击运行吗
.cpp .c source 源文件 文本 ❌ 电脑看不懂
.h header 头文件 文本声明 ❌
.o object file 目标文件 机器码 ❌ 缺依赖
.a static library 静态库 机器码集合 ❌ 给链接器看
.dll dynamic lib 动态库 机器码集合 ❌ 需 exe 加载
.lib library MSVC 库 机器码集合 ❌
.exe executable 可执行文件 机器码 ✅ 可以
.pdb program db 调试符号 调试信息 ❌ 配合 exe

命名规则（很实用）

库文件名 ≠ 命令行参数

磁盘上的文件 命令里要写
libglfw3.a -lglfw3
libgdi32.a -lgdi32
libgl.so（Linux 动态库） -lgl
libGL.so -lGL

规则：去掉 lib 前缀和后缀（.a / .so / .lib），只写中间部分。
lib 和后缀都是给操作系统识别用的，编译器参数里不写。

Linux 补充：.a 结尾 = 静态库，.so 结尾 = 动态库。
所以 libglfw3.a 和 libglfw3.so 是同一个库的两个版本。

四、g++ 命令逐符号详解

这是整份笔记最重要的部分。

符号 读作 作用阶段 含义
g++ 编译 C++ — 必须是 g++，不能是 gcc
src/main.cpp 输入 编译 要编译的源文件
-o src/main.exe output 链接 输出文件名
-g generate debug 编译 生成调试信息，供断点使用
-I（大写 i） include 预处理 去哪找 #include 的头文件
-L（大写 l） library path 链接 去哪找库文件
-l（小写 l） link 链接 要链接哪个库
-c compile only 编译 只生成 .o，不链接、不生成 exe

三个最易踩的坑

坑 1：gcc vs g++

  • gcc 按 C 语言规则编译，遇到 iostream、std:: 之类会报错
  • g++ 会自动链接 C++ 标准库
  • 规则：.c 用 gcc，.cpp 用 g++。记不住就全用 g++。

坑 2：-I 大小写写错

  • -I（大写）= 头文件路径
  • -l（小写）= 库名
  • -L（大写）= 库路径
  • 写错大小写编译器会报"未知选项"

坑 3：找不到头文件 vs 找不到库，是两个不同的问题

报错 含义 改哪个参数
fatal error: GLFW/glfw3.h: No such file 头文件找不到 -I
undefined reference to glfwInit 库没链上 -L 或 -l

记住这个规律，能省掉大量猜测时间。

五、静态库 vs 动态库

静态库 .a 动态库 .dll
代码怎么进 exe 整个复制进去 只存引用，运行时加载
exe 大小 较大 较小
分发 一个 exe 走天下 要附带 dll 文件
内存 多个程序各占一份 可共享同一份

为什么 GLFW 走静态库路线？
因为 GLFW 官方在 Windows 上不提供 MinGW 编译的二进制库（只提供 MSVC 的 .lib）。而 MSVC 的 .lib 你的 g++ 用不了。所以只能下载源码自己编译 → 得到 .a。

六、CMake 是什么

一句话定义

CMake 是一个"写代码描述项目该怎么编译"的工具，自己不编译任何东西。

核心误解澄清

新手常以为 cmake 命令跑完就有 exe 了。并没有。

工具 身份 干什么 产出什么
CMake 配置器 读 CMakeLists.txt，生成构建脚本 Makefile
Make 调度器 按脚本逐步执行 调用编译器
G++ 编译器 翻译代码 .o / .a / .exe

类比：

  • CMake = 建筑图纸（画图，不施工）
  • Make = 施工队调度（按图派工）
  • G++ = 实际干活的工人
  • .exe = 盖好的房子

图纸画错了房子会塌，但图纸本身不会变成房子。

CMakeLists.txt 示例与逐行解释

指令 作用 对应的手写命令
cmake_minimum_required(VERSION 3.16) 声明最低 CMake 版本 —
project(MyGLFWDemo C) 项目名，指定主要语言 —
add_executable(demo src/main.cpp) 我要一个可执行文件 -o demo.exe
add_library(glfw STATIC src/window.c ...) 我要一个静态库 ar rcs libglfw3.a
target_link_libraries(demo PRIVATE ...) 要链接哪些库 -lglfw3 -lgdi32
target_include_directories(demo PRIVATE ...) 头文件在哪 -I路径

关键洞察：add_executable + target_link_libraries 就是
g++ main.cpp -o main.exe -lglfw3 的翻版。
主语从"你"换成"CMake"而已，本质完全一样。

-G 生成器可选值

-G 值 生成什么 用什么执行
"MinGW Makefiles" Makefile make
"Ninja" build.ninja ninja（更快）
"Visual Studio 17 2022" VS 工程 Visual Studio

VS 2026 的 OpenGL 向导，本质就是帮你生成 CMake 配置 + VS 工程。
这就是为什么它和 VS Code 的 CMake 是同一条路。

什么时候该用 CMake

现在这个阶段：可以不用。 手打 g++ 命令能让你真正搞懂 -I -L -l。

出现这些信号时再引入：

  • 项目有 5 个以上源文件
  • 想生成库给别人用（不只是 exe）
  • 引入 GLAD + 着色器文件后，命令行变得很长
  • 想换编译器或换系统而不用重写配置

七、GLFW 是什么

OpenGL 生态的四个角色

名字 身份 负责什么
OpenGL 一套规范（标准） 定义"画三角形/纹理"有哪些函数
显卡驱动 Windows 自带 真正实现这套规范，指挥 GPU 干活
GLFW 第三方库 创建窗口、处理键鼠、管理 OpenGL 上下文
GLAD 第三方库 加载 OpenGL 函数指针（现代 3.3+ 必需）

为什么必须有 GLFW？
OpenGL 规范里根本没有"创建窗口"这个功能（它只管画）。窗口是操作系统的概念，所以必须靠 GLFW 这类库补上。

一句话总结：OpenGL 负责"画"，GLFW 负责"给你一个能画的窗口"。

关键概念：上下文（Context）

glfwCreateWindow() 创建窗口时，会同时创建一个 OpenGL 上下文。

上下文 = "当前往哪个窗口画"的状态。

OpenGL 的所有画图命令都必须有个作用目标，所以必须先调
glfwMakeContextCurrent(window) 告诉系统"从现在开始往这个窗口画"。

常见坑：一程序里开多个窗口时，切换窗口后必须重新调用
glfwMakeContextCurrent()，否则会画到错误的窗口。

九、VS Code 三个配置文件

为什么要配置文件？

VS 2026 的"OpenGL 项目向导"本质上就是生成一份编译参数记录。
VS Code 用 JSON 文件记录同样的信息，三者一一对应：

信息 VS 存在哪 VS Code 存在哪
头文件在哪 项目属性 → C/C++ → 附加包含目录 c_cpp_properties.json
库文件在哪 链接器 → 附加库目录 tasks.json 的 -L
链接哪些库 链接器 → 附加依赖项 tasks.json 的 -l

没有神秘差异，不需要装 VS。

文件一：tasks.json —— 负责编译

Ctrl+Shift+B 执行的就是这里定义的命令。

四个核心变量（VS Code 的灵魂）

变量 展开成什么 用途
${file} 当前编辑文件的完整路径 总是编译你正在看的文件
${fileDirname} 该文件所在文件夹 输出 exe 放同目录
${fileBasenameNoExtension} main（去掉 .cpp） 拼出 main.exe
${workspaceFolder} VS Code 打开的那个文件夹 定位 GLFW 库，与打开哪个文件无关

用变量的好处：新建 triangle.cpp、texture.cpp 后，按 Ctrl+Shift+B 自动编译成对应 exe，一个配置通用所有文件。

其他字段的作用

字段 作用 能省吗
problemMatcher: ["$gcc"] 让 VS Code 解析报错并标到对应代码行 别省，否则报错是纯文本
type: "cppbuild" 自动弹出终端面板显示输出 建议保留
isDefault: true 让 Ctrl+Shift+B 命中这个任务 保留

文件二：c_cpp_properties.json —— 负责代码提示

不影响编译能否成功，只影响编辑体验：红线、自动补全、鼠标悬停显示函数签名。

原理：告诉 VS Code 智能引擎"假装你是这个编译器，按这些路径找头文件"。

字段 改动说明
includePath 多一行指向 GLFW 的 include → 红线消失、补全生效
compilerPath 指向 g++ → 引擎按 C++ 规则解析
cppStandard c++17 → 按 C++17 语法解析
intelliSenseMode windows-gcc-x64 → 告诉引擎这是 Windows 上的 MinGW 64 位

填路径的两个坑

  1. 路径里不能用中文（很多工具链不支持）
  2. 有些版本要求去掉 .exe 后缀 —— 如果改完红线还在，把 .exe 删掉再试

找不到编译器路径？ 终端跑 g++ -v，输出里能看到路径。

文件三：launch.json —— 负责调试

想用断点、单步执行（F10 逐行、F11 进函数）时需要。

Ctrl+Shift+P → 「C/C++: Add Debug Configuration」→ 选 g++ → 选 main.cpp，自动生成。

字段 作用 坑
program 要调试的 exe 路径 必须和 tasks.json 的 -o 输出完全一致
miDebuggerPath gdb 路径 必须绝对路径，写 gdb 会找不到
externalConsole: true 额外弹出黑色控制台 OpenGL 必开，见下

⚠️ externalConsole 对 OpenGL 至关重要

没有它，OpenGL 程序启动后会立即闪退。

原因：OpenGL 程序需要控制台来维持进程生命周期。没有控制台窗口，
主函数返回后进程立刻结束，你根本看不到窗口。

开启后：额外弹出一个黑色控制台窗口，程序结束后自动关闭，
你还能在那里看到 std::cout 输出的错误信息。

按键 功能
F5 启动 / 从断点继续

主循环原理（新手最困惑处）

你的代码不是"画完就停"，而是每秒重复执行几千次。

程序内部实际是这样循环的：

函数 作用 不写会怎样
glClearColor(r,g,b,a) 设置"清屏用什么颜色"，范围 0.0~1.0 用默认黑色
glClear(GL_COLOR_BUFFER_BIT) 真正执行清屏 看到上一帧残留，图像堆积成鬼影
glfwSwapBuffers(w) 把后台画的内容推到前台显示 窗口白屏/闪烁
glfwPollEvents() 检查用户有没有点关闭/按键 窗口关不掉
glfwWindowShouldClose(w) 循环退出条件 —

双缓冲原理

Windows 有两个缓冲区：

  • 后台缓冲：你的代码在这里画
  • 前台缓冲：用户看到的内容

glfwSwapBuffers() 把后台"啪"地推到前台，然后你就能在后台画下一帧。
人眼看不完几千帧的切换，所以感觉是连续动画。

双缓冲存在的意义：如果只有一个缓冲区，你画到一半用户就看到了，
会看到半成品画面（撕裂、闪烁）。两个缓冲交换能保证用户看到的永远是完整一帧。

常见 bug："我明明设置了颜色，窗口怎么没变色？"
99% 是忘了调 glfwSwapBuffers()，画的东西根本没显示出来。

glfwSetErrorCallback 会把 GLFW 的所有错误打印出来，调试时非常有用。

为什么短短几行C++程序会有2~3MB这么大?

核心原因

你写的短短几行C++代码，编译出来exe达到2MB，不是你的代码本身大，是编译器默认把C++标准库（运行时库）打包进exe里面了，这个叫静态链接。

1. 静态链接（默认很多IDE：Dev-C++、MinGW）

举例子：

你只写了输出一句话。
但是cout属于C++标准库，静态链接时：
✅ 编译器把整个libstdc++库里面你用到的代码，复制打包进exe
哪怕只用了一点点cout，也要带上一大段底层IO、内存管理代码。
结果：exe 1~3MB很常见。

就像：你只是想用一把螺丝刀，但是静态打包直接把整个工具箱一起塞给你。

2. 动态链接（可以让exe很小，几十KB）

动态链接：不把库打包进exe，exe运行时去调用系统里单独存在的dll文件。
缺点：换一台电脑运行，如果缺少对应的dll，程序直接打不开。
所以MinGW默认静态打包，保证拷到别的电脑可以直接运行。

3. 额外增大体积的其他因素

  1. Debug调试模式（罪魁祸首！）
    Debug版本会额外嵌入大量调试信息、符号表。同样代码，Debug版体积远大于Release发布版。
    👉 想缩小体积：切换到Release模式编译。
  2. 没有开启代码优化，保留很多无用代码。
  3. 如果你用的是64位编译器，生成的程序本身会比32位更大。

✅ 怎么缩小exe体积（MinGW/g++）

  1. 切换到Release（关闭调试符号）
  2. 编译时加优化参数：
  • -Os：体积优化
  • -s：删掉所有调试符号信息
    加完，这个cout小程序，能压缩到几百KB。

一句话区分考点（应付考试）

  • 静态链接：库代码复制进exe，文件大，可独立运行，不依赖外部dll
  • 动态链接：库放在外部dll，exe很小，依赖系统dll文件

PS: PE文件格式+CPU寻址机制限制, exe大小应当在 4GB 以下

C++游戏开发:储备知识

classes, templates, smart pointers, and the STL（C++）简单介绍

1. Classes 类

C++面向对象的核心，封装数据与操作数据的函数。

  • 把成员变量（属性）、成员函数（行为）打包成一个类型。
  • 支持访问控制：public/private/protected，实现封装；还支持继承、多态。

2. Templates 模板

泛型编程工具，让函数/类不绑定具体类型，一份代码可以适配多种数据类型。

  • 函数模板：同一个函数可以处理 int、double、string 等。
  • 类模板：最典型就是 std::vector<T>，T 就是模板参数。

3. Smart pointers 智能指针

自动管理堆内存的指针，替代裸指针，解决内存泄漏问题，本质是RAII（资源获取即初始化）。

  • std::unique_ptr：独占所有权，不能拷贝，只能移动；开销最小。
  • std::shared_ptr：共享所有权，引用计数，计数归零自动释放内存。
  • std::weak_ptr：配合 shared_ptr，解决循环引用，不增加引用计数。

核心：离开作用域时自动析构释放内存，不用手动 delete。

4. STL（Standard Template Library）标准模板库

C++标准库的泛型组件集合，全部基于模板实现，分4大块：

  1. 容器 Containers：存放数据。vector、string、map、unordered_map、set、deque、list。
  2. 迭代器 Iterators：容器的“指针”，统一遍历不同容器。
  3. 算法 Algorithms：通用函数，sort、find、for_each，通过迭代器操作容器。
  4. 函数对象 Functors：可调用对象，用于算法自定义行为。

一句话总结

  • Class：面向对象，封装；
  • Template：泛型，类型无关代码；
  • Smart pointer：安全自动内存管理；
  • STL：一套现成模板容器+算法库，日常C++开发主力。

二、C++内存管理难点（游戏开发场景）

C++没有GC，内存生命周期完全由程序员手动控制。错误常表现为间歇性bug，Debug正常Release随机崩溃。

  1. 栈 vs 堆
    栈：局部变量，函数退出自动销毁；栈空间很小，大数组容易栈溢出。
    堆：new分配，必须手动delete；适合大量实体、地图数据。

坑：保存栈对象指针到全局队列，函数退出对象销毁 → 悬垂指针。

  1. 悬垂指针（野指针）
    指针还存在，但指向内存已经释放。访问时属于未定义行为，可能乱数据、随机崩溃。回合行动队列极易踩坑。
  2. 内存泄漏new之后忘记delete。敌人死亡不释放内存，长时间游玩内存持续上涨。程序不会报错，只会慢慢吃内存。
  3. 重复释放 double free
    一块内存delete后再次delete，破坏堆结构，随机崩溃。典型场景：ECS实体多处写删除逻辑。
  4. 浅拷贝陷阱
    默认拷贝仅复制指针，两个对象共用同一块堆内存；一个析构后另一个指针失效。角色、物品结构体高频踩坑。
    解决：手写深拷贝，或禁用拷贝。
  5. 内存所有权问题
    谁负责释放内存？行动队列保存Action指针时，如果所有权约定不清，极易出现泄漏或double free。
    现代C++方案：std::unique_ptr（单一所有权，优先推荐）；谨慎使用std::shared_ptr（循环引用会泄漏）。
  6. new[] / delete[] 必须配对
    数组分配new[]，释放必须用delete[]，混用为未定义行为。
  7. 未定义行为 UB
    内存错误没有固定报错表现：可能正常运行、随机崩溃、只在打包后出错，bug根源和崩溃位置不在一起。

✅ 降低C++内存风险的工程规范（回合引擎推荐）

  1. 优先栈对象，临时Action、小结构体尽量栈分配。
  2. 容器优先值语义：std::vector<Entity>，而不是vector<Entity*>，vector自动管理内存。ECS组件数组推荐这种写法。
  3. 堆对象优先std::unique_ptr，少用shared_ptr。
  4. 实体用ID代替裸指针（强烈推荐）
    实体使用uint64_t整数ID；维护unordered_map<uint64_t, Entity>。所有Action、buff、AI只存实体ID，访问实体通过ID查找。实体销毁直接删除map条目，直接消灭悬垂指针。

一句话总结：C++内存难不在于语法，而在于手动管理生命周期与所有权；错误行为飘忽，难以定位。
